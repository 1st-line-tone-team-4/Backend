# A+B integration coordination

Source: main Notion contract 1.3.0-backend-proposal, fetched 2026-10-31; `contracts/` contains Notion code blocks, not Library materializations. Python 3.12, FastAPI, SQLAlchemy 2; SQLite isolated tests and a separate disposable MySQL verification path.

## Current integration scope — supersedes the original B-only scope

The user authorized A+B integration and fixes in the integration worktree. The original B-only instruction to leave A domains unimplemented is historical and no longer applies to this integration. One `app.main:create_app` factory mounts both sets of routes, and one worker registers analysis/questions/learning_explanation/grade/message/report handlers. There is no independent A runtime, ORM registry or engine. `language_learning_api.main` reexports the shared factory.

`app.models.Base` defines all 35 canonical tables; the active SQL migration chain is 000–005. Experimental A Alembic revisions are quarantined and explicitly blocked from execution. All IDs use the CHAR(36)/string contract, with UUID-object bind compatibility. New schemas and existing B004 upgrades must follow `migrations/README.md`; existing independent A databases are not claimed compatible.

External RS256 JWTs are verified by the shared authenticator. The first valid issuer/subject pair provisions a local user; password signup/login and token issuance are not implemented. The default runtime task gateway is `CanonicalTaskGateway`, reading actual A rows in the same transaction. Publication creation/public solving/score review/billing business routes remain outside this integration, although their contract tables and private existing public-attempt history reads are present.

Use `requirements.lock` as the sole dependency lock, then `python -m pip install --no-deps -e .` to register both packages. The old standalone A `uv.lock` is not an installation path for this integrated server. Current setup and frontend prerequisites are in `README.md`; actual mounted API inventory is 40 paths / 51 operations (B24 + A27).

This integration does not authorize real provider keys/calls, production DB access, deployment, main merge, force push or external messages/Notion writes. Follow the user's current authorization and the orchestrator's live file ownership assignments.

## Shared interfaces (coordinate changes with orchestrator)

SQLAlchemy ORM classes live in app.models and match SQL column names in contracts. A goals, plans/task pins, attempts, sessions/messages, reports/items/evidence and actions/feedback now use complete normalized tables alongside B content and shared jobs/idempotency. `src/language_learning_api/models.py` only reexports canonical classes; do not add duplicate shared tables or denormalized B data. Additional internal state columns must be documented. Prefer explicit `session.flush()` dependency order, no ORM relationships needed. `uid()` -> str UUID, `utcnow()` -> naive UTC datetime, `iso(dt)` -> UTC RFC3339 string in core.

`Database(url)` has `engine`, `session_factory`, `create_schema()` for isolated development/test only, `transaction()` context manager yields Session and commits/rolls back. SQLite foreign keys enabled, bounded busy timeout. `ApiError(status, code, message, details=None)` and app exception handler yields contract ErrorEnvelope with request_id; never include request bodies/keys in errors. `Settings` dataclass provides profile ('production' default), database_url, storage_root, public_base_url, credential_encryption_key, signing_secret, auth_public_key, auth_issuer, auth_audience, enabled_models tuple. Production must fail closed without real auth/config; test auth exists only inside tests.

`get_context(request)` returns `request.app.state.context`; `get_user(request)` delegates context.auth.authenticate(request) -> owner UUID string, never accepts arbitrary headers in production. Context SimpleNamespace assembled by orchestrator: settings, db, auth, storage, providers, credentials, jobs, task_gateway. B routers use relative paths mounted under /v1; the existing A routers include their /v1 prefix and are mounted without a second prefix.

`idempotent(ctx, user_id, operation, key, request_data, action)` in core: validates key 16..128, canonical request_data includes method/path/query/body (excludes X-AI-Key); same owner/operation/key replays status/body; mismatch 409; callback action(session)->(status, JSON-serializable body), domain change and replay persisted in same transaction; handles concurrent constraint errors. Returns JSONResponse. POST routes use this. Non-POST use transaction().

JobService(ctx): `enqueue(session, *, user_id, kind, resource_type, resource_id, payload, model_id, ai_key) -> Job`; `register(kind, handler)`; `run_once() -> bool`; job rows available on session.flush before caller links resource. No callback commits. handler interface: `prepare(session, job) -> dict` returns prompt data; `persist(session, job, output:dict) -> str` validates output and saves domain records and returns owner GET result URL; `set_state(session, job, state: str)` supports queued/running/succeeded/failed/outcome_unknown and latest-job guard; `is_current(session, job)->bool` (used retry/restart/fencing). Provider call shape `ctx.providers.generate(model_id, key, kind, payload)->dict`; provider registry `list_models()`, `validate_key(model_id,key)`, `ensure_model(model_id)` returns None or raises ApiError. Credentials APIs agreed by jobs agent internally. Jobs routers implement contract /ai/models, /ai/validate-key, /jobs/{id}, /retry, /restart. Unknown outcome never automatically repeats a provider call; retry only definite pre-call/transient failures; terminal secret deletion; leases/fencing/crash tests. Additional internal cancel method okay, document absence from public contract.

Materials exports `router` and `AnalysisHandler(ctx)`. Context storage implementation from materials agent provides signed PUT/GET via explicit local private storage adapter (production supported only with strong signing/TLS configuration), upload body route, validate+extract upload for analysis; test uses same filesystem path isolated tmp. Source URLs carry expiring purpose-bound token with file id/owner; no arbitrary paths. Signed storage routes may mount alongside /v1 with explicitly documented internal adapter prefix. Material methods use immutable confirmed versions; helpers `get_confirmed_version(session, user_id, concept_version_id, require_current=False)` returns ORM version with owner/material/confirmed verification; `evidence_dto(session, chunk_id, excerpt=None)`; `version_dto(session, version)`.

Content exports `router`, `QuestionsHandler(ctx)`, `ExplanationHandler(ctx)`, `get_grading_question(session,user_id,question_id)` internal A adapter. The default `app.a_gateway.CanonicalTaskGateway` implements the app.ports interfaces using real A rows, the supplied transaction and shared goal/plan/task locking rules. The immutable QuestionTaskState includes task/owner/unit IDs, pinned concept version IDs, task_type, active_revision (strict boolean), target_count and authoritative completed_count. Shared `validate_question_task(session,user_id,task_id,unit_id,concept_version_ids,*,count)` validates ownership, active plan revision, exact pins, solve type and remaining target. The bare, unconfigured TaskGateway still fails closed, but it is not the integration factory default. `material_in_use` checks actual A references; `read_question_attempts` returns actual owned attempts. Fixture gateways are test substitutions only. B question generation does not increment task progress.

Read full scoped request/response schemas in contracts before implementing. Preserve snake_case and exact status enums. Public Question excludes answer/rationale; internal adapter exposes them only after owner check. Include meaningful adversarial tests, not only happy paths. Never print/log/store raw BYOK keys outside encrypted TTL vault. Send implementation uncertainties immediately.

## N-series runtime boundary update

Generation is bounded to 300s, key validation to 15s. JobService default lease420s must strictly exceed generation300s + prepare60s. Analysis handlers implement prepare_snapshot(session,job), prepare_external(snapshot), apply_prepared(session,job,prepared), persist_prepared(session,job,output,prepared); only prepare_external may perform storage/parsing I/O. Other A handlers must keep their legacy prepare SQL-only or implement this split.

validateAIKey uses its own short durable claim around non-generating HTTP, with an owner/model/key server HMAC incorporated only into the request digest. Other generic idempotent operations still exclude X-AI-Key. core.idempotency_replay performs a read-only preflight replay before expensive preparation; final idempotent action must recheck domain state. New vault references are removed on known rollback, retained within existing TTL on uncertain COMMIT, and old retry references are retired only after commit. Terminal material Job rows survive source deletion with request_payload/result_url/credential reference redacted.
