## Shared interfaces (coordinate changes with orchestrator)

SQLAlchemy ORM classes in app.models, matching SQL names in contracts: User, Job (ai_jobs), Material, MaterialUnit, MaterialChunk, Concept, ConceptVersion, ConceptChecklistItem, ConceptVersionEvidence, QuestionSet, QuestionSetConcept, Question, QuestionEvidence, LearningExplanation, LearningExplanationEvidence, IdempotencyRequest, StorageDeletion. Minimal A reference tables only where FK needed; no A routes. Class attributes match SQL column names. Additional internal state columns allowed only if documented. Prefer explicit `session.flush()` dependency order, no ORM relationships needed. `uid()` -> str UUID, `utcnow()` -> naive UTC datetime, `iso(dt)` -> UTC RFC3339 string in core.

`Database(url)` has `engine`, `session_factory`, `create_schema()` for isolated development/test only, `transaction()` context manager yields Session and commits/rolls back. SQLite foreign keys enabled, bounded busy timeout. `ApiError(status, code, message, details=None)` and app exception handler yields contract ErrorEnvelope with request_id; never include request bodies/keys in errors. `Settings` dataclass provides profile ('production' default), database_url, storage_root, public_base_url, credential_encryption_key, signing_secret, auth_public_key, auth_issuer, auth_audience, enabled_models tuple. Production must fail closed without real auth/config; test auth exists only inside tests.

`get_context(request)` returns `request.app.state.context`; `get_user(request)` delegates context.auth.authenticate(request) -> owner UUID string, never accepts arbitrary headers in production. Context SimpleNamespace assembled by orchestrator: settings, db, auth, storage, providers, credentials, jobs, task_gateway. Routers use `APIRouter` with paths starting /materials etc (app mounts /v1).

`idempotent(ctx, user_id, operation, key, request_data, action)` in core: validates key 16..128, canonical request_data includes method/path/query/body (excludes X-AI-Key); same owner/operation/key replays status/body; mismatch 409; callback action(session)->(status, JSON-serializable body), domain change and replay persisted in same transaction; handles concurrent constraint errors. Returns JSONResponse. POST routes use this. Non-POST use transaction().

JobService(ctx): `enqueue(session, *, user_id, kind, resource_type, resource_id, payload, model_id, ai_key) -> Job`; `register(kind, handler)`; `run_once() -> bool`; job rows available on session.flush before caller links resource. No callback commits. handler interface: `prepare(session, job) -> dict` returns prompt data; `persist(session, job, output:dict) -> str` validates output and saves domain records and returns owner GET result URL; `set_state(session, job, state: str)` supports queued/running/succeeded/failed/outcome_unknown/cancelled and latest-job guard; `is_current(session, job)->bool` (used retry/restart/fencing). Provider call shape `ctx.providers.generate(model_id, key, kind, payload)->dict`; provider registry `list_models()`, `validate_key(model_id,key)`, `ensure_model(model_id)` returns None or raises ApiError. Credentials APIs agreed by jobs agent internally. Jobs routers implement contract /ai/models, /ai/validate-key, /jobs/{id}, /retry, /restart. Unknown outcome never automatically repeats a provider call; retry only definite pre-call/transient failures; terminal secret deletion; leases/fencing/crash tests. Additional internal cancel method okay, document absence from public contract.
